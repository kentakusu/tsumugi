# 紡（tsumugi）

Claude Code を無人で走らせるための**仕組み**です。指示書・設計・道具を置きます。

**知識は置きません。** 知識は手元の [結（yui）](https://github.com/kentakusu/yui) に入れます。

| | 何を持つか | どこに在るか |
|---|---|---|
| **紡** | 仕組み（動かし方・決めごと・道具） | このリポジトリ（公開） |
| **結** | 知識（所属ごとの事情・手順・経緯） | 手元の `*.yui`（公開しない） |

## これは何か

作者が自分の運用に使うためのものです。**他の方が使われるなら「緩い前提」でお願いします。**
壊れても直す約束はしていません。

## 決めていること

- **Claude Code 前提です。** 他の AI 製品で動くことは狙いません。
- **tmux を使いません。** 依存を増やさないためです。セッション同士のやり取りは、
  Claude Code 標準のエージェント間メッセージ（`ListAgents` / `SendMessage`）を土台にします。
- **Claude Code のローカルメモリに頼りません。** 複数のクライアントや状況にまたがる知識は
  結に入れ、どこから起動しても同じものを引きます。
- **所属ごとに設定を分けます。** 仕組みは 1 つで共通、所属ごとのルール・知識・認証は
  手元の設定だけが持ちます（例: 自社 / 個人 / 業務委託先 A / 業務委託先 B）。
  手元を適切に設定すれば動く、を目指します。

## このリポジトリに入れないもの

- 結のデータ（`*.yui`）
- 所属ごとの設定と知識（`~/.tsumugi/` に置く。リポジトリの外）
- 認証情報

`.gitignore` で弾いていますが、**最後に確かめるのは commit する人です。**

## 状態

| コマンド | 状態 |
|---|---|
| `tsumugi status` | 在る。所属ごとに「要るセッション」と「実際に動いているもの」を並べる |
| `tsumugi run` | 在る。足りないものを起こし、紡が起こして要らなくなったものを止める（1 回流して終わる。`--dry` で見るだけ） |
| `tsumugi list`（`l`） | 在る。`claude agents` の行を同じ並び・同じ ID・同じ名前・同じ様子で全部出し、紡では何か（所属/セッション・前の会話・紡の外）と `tsumugi a` の番号を添える。毎回 `claude agents` から作るので、`claude` を直接打った変更もそのまま映る。所属.json にあるのに `claude agents` に無いもの（まだ起こしていない・外された）は下の段に別に出す |
| `tsumugi tree`（`木`） | 在る。セッションごとに、いまの会話と前の会話（写しになった・新しく立て直した・片付けた）を木の形で並べる。紡の外は作業フォルダごと |
| `tsumugi 定時`（`schedules`） | 在る。所属.json の定時をセッションごとに並べる（いつ・次に届く時刻・最後に届けた時刻・止めてある／よそのマシンなら届かないこと・指示の頭）。読むだけ |
| `tsumugi 止める`（`stop`）`<名前|番号> [--しばらく] [--強制]` | 在る。控えの会話 ID で `claude stop` する（控えは残るので、次に起こしても同じ会話）。作業中は断る（`--強制` で止める）。常駐のものは次の run が起こし直すので、止めたままにするなら `--しばらく`: `tsumugi a` で起こすまで、run・定時・届けで起こさない（届けは溜める）。一覧には「止めてある」で残る |
| `tsumugi 外す`（`rm`）`<名前|番号> [--強制]` | 在る。紡の一覧から消す。止めて、いまの会話と前の会話を `claude rm` し、所属.json の項と控えを消す。会話の記録は残る（所属.json に「引き継ぐ会話」で足せば戻せる） |
| `tsumugi 新しく`（`renew`）`<名前|番号> [--すぐ]` | 在る。同じ名前のまま、新しい会話で最初の指示から始め直す（会話が長くなりすぎたとき・Remote Control の名前が付け替わってしまったとき）。動いていれば、先にチャネルで「申し送りを結の現在地に書いて」と頼み、書き終えて空くまで待つ（最大 10 分・`--すぐ` で飛ばす）。そのあと止めて `claude rm`（スマホの一覧からも消える）、前の会話として残し、「前の会話（ID）から新しく起こし直した」知らせ付きの最初の指示で起こす。自分自身と作業中のセッションは断る |
| `tsumugi attach`（`a`）`<名前\|番号\|ID>` | 在る。開く。番号は `list` の左端。止まっていれば同じ会話のまま起こしてから開く |
| `tsumugi 届ける`（`send`）`<名前> [指示…]` | 在る。外（受け口・人・道具）からセッションへ指示を渡す。すぐ渡せなければ `<所属>/届け待ち/` に置き、run が渡す（24 時間で諦めて知らせる） |
| `tsumugi 更新`（`update`）`[--dry] [紡\|claude\|OS\|設定項目]…` | 在る。項目を書けばそれだけ（例: `tsumugi 更新 紡`）。Claude Code（`claude update`）と OS のパッケージ（Ubuntu: apt / macOS: brew / Windows: winget）を新しくする。`紡.json` の「更新」に時刻を書けば run が毎日やる。古い版で動いている空きセッションを、同じ会話のまま入れ直す |
| `tsumugi 設定項目`（`settings`）`[--dry]` | 在る。Claude Code の設定項目の一覧を取り、前回からの増減と、手元の設定にある「一覧に無い鍵」を出す |
| `tsumugi 名前を変える`（`rename`）`<いまの名前> <新しい名前>` | 在る。紡のセッションの名前を変える。Claude Code に外から名前を変える口が無く、セッションは名前を環境変数でも持つので、**同じ会話を引き継いで新しい名前で起こし直す**（会話 ID は新しくなる）。定時の記録・届け待ちも移す。自分自身と作業中のセッションは断る |
| `tsumugi 設定そろえ`（`align-settings`）`[--dry]` | 在る。Claude Code のユーザー設定（`~/.claude/settings.json`）を、基本の値 [`settings/claude-base.json`](settings/claude-base.json) と比べる。書き換えるのは `紡.json` の `"設定を合わせる"` に載せた鍵だけ（`["*"]` で全部）。前の値・後の値を `<手元>/設定そろえの記録.log` に残す。毎日の更新（`設定項目`）でも見る |
| `tsumugi チャネル準備`（`channel-setup`） | 在る。動いているセッションへ**止めずに**渡すチャネル（Claude Code の channels・研究プレビュー）の準備。プラグインを入れ、マシンの管理設定に許可があるかを見る（無ければ打つものを出す） |
| `tsumugi yui <問い合わせ>…` | 在る。結のデーモンに名乗って問い合わせる。紡のセッションは結をこれで読み書きする |
| `tsumugi install` / `uninstall` | 在る。OS の定期実行に `tsumugi run`（5 分おき）を登録する / 外す。Linux（systemd の user timer）・Windows（タスク スケジューラ・管理者不要・TSUMUGI_HOME もタスクに渡る）・macOS（launchd・2026-11-22 Mac mini で実測）で確かめた |

純正機能との対応（純正でできることは純正に寄せる）は [docs/純正との対応.md](docs/純正との対応.md)。
設計は [docs/設計.md](docs/設計.md)、日々の使い方（前面と背景の行き来など）は [docs/使い方.md](docs/使い方.md)。

## 作り方

Go 1.27 が要ります。

```
go build -o tsumugi ./cmd/tsumugi      # Windows なら -o tsumugi.exe
go test ./...
```

Linux（Ubuntu）・Windows・macOS（Apple Silicon）で動かして確かめています。

## 所属の設定

`~/.tsumugi/<所属>/所属.json`（置き場所は環境変数 `TSUMUGI_HOME` で変えられます）。
フォルダ名がそのまま所属の名前になります。

```json
{
  "表示名": "自社",
  "セッション": [
    {
      "名前": "jisha-keiri",
      "作業フォルダ": "~/jisha-keiri",
      "最初の指示": "docs/TASK.md を読んで、話しかけられるまで待つ",
      "権限モード": "dontAsk"
    }
  ]
}
```

所属.json の知らないキーは誤記として弾きます（黙って捨てません）。
`紡.json` の知らないキーは、新しい版の紡が足したものかもしれないので、飛ばして読み、知らせます（古い版の紡で、マシン名やチャネルまで読めなくならないように）。
★`紡.json` に新しいキーを足すときは、**先に各マシンの紡を新しくしてから**足してください。

所属ごとに `見張り` を書けます（書かなくても既定で見張り、run の出力に残します）:

```json
"見張り": { "止まり": "15m", "長すぎ": "3h", "知らせる": ["~/bin/notify.sh"] }
```

run のたびに、紡のセッションの様子（`claude agents --json` の state）を見て、
`blocked`（権限の確認・入力待ち）が `止まり` だけ、作業中が `長すぎ` だけ続いたら、1 回だけ知らせます。
`知らせる` はコマンドで、本文を標準入力と環境変数 `TSUMUGI_MESSAGE` で渡します（LW へ送る道具などを書く）。
紡のセッションに知らせるなら `["tsumugi", "届ける", "<名前>"]`（run の中からは届け待ちに置くだけで、次の run が渡す）。
届けを諦めたときも、ここへ知らせます（★`知らせる` が無いあいだは、届けを諦めずに置いておきます。黙って捨てないため）。

所属をまたぐ設定は `~/.tsumugi/紡.json` に置きます。このマシンの名前と、結のデーモンのアドレスです。

```json
{ "マシン": "myhost/Ubuntu", "結": { "アドレス": "127.0.0.1:7952" } }
```

チャネル（動いているセッションへ止めずに渡す）: `tsumugi チャネル準備` が全部 ○ になったら `"チャネル": true` を足す。
紡が起こすセッションに `--channels plugin:tsumugi-channel@tsumugi` が付き、定時と届けはソケット（`<手元>/<所属>/<名前>.sock`）
へ書くだけになる（止めない・作業中でも次のターンで入る）。チャネルが応えないセッションには、今までどおり止めて渡す。

更新（セキュリティのため、いつも最新を使う）:

```json
"更新": { "いつ": "30 4 * * *", "紡": true, "claude": true, "OS": true, "入れ直し": true, "設定項目": true,
          "ほか": [["mise", "upgrade"]], "知らせる": ["~/bin/notify.sh"] }
```

| キー | 意味 |
|---|---|
| `いつ` | cron 5 項目。来たら run が 1 回 更新する（書かなければ `tsumugi 更新` を手で）。機械が寝ていて逃しても、24 時間以内に起きれば追いかける。更新は run とは別の錠で回すので、長い更新の間もほかの run は起こす・届けるを続ける。1 つのコマンドは 2 時間で打ち切る |
| `紡` | 紡そのものを新しくする。main に push するたびに Actions が各 OS 向けの実行ファイルを [Release](https://github.com/kentakusu/tsumugi/releases) に置くので、それを取り、`SHA256SUMS` で確かめてから置き換える。Release のほうが新しいときだけ（手元の変更が入ったビルドは置き換えない）。Windows は動いている exe を `.old` に退けてから置く |
| `claude` | `claude update`（純正の更新を呼ぶだけ） |
| `OS` | Ubuntu/Debian: `sudo -n apt-get update` と `upgrade`（パスワードを聞かれる環境では止まらず失敗として知らせる）／macOS: `brew update`・`brew upgrade`／Windows: `winget upgrade --all --scope user --silent`（管理者権限が要るものは無人では入らないので、残りを一覧にして記録に出す。人が手で入れる）。毎日の更新から外したいものは純正の `winget pin add --id <ID>`（ブロックでない種類）で外し、外しているものは毎回 `winget pin list` として記録に出す。pin は一覧と `--all` からは外れるが、`--id` で名指しした upgrade は止めない。**再起動はしない**（要るときは知らせる） |
| `ほか` | ほかに流すコマンドの並び |
| `入れ直し` | run のたびに、claude の実行ファイルより前に起きた・空いている紡のセッションを、同じ会話のまま起こし直す（作業中・入力待ちには触らない） |
| `設定項目` | 設定項目の一覧（SchemaStore の JSON Schema）を取り、増減と「一覧に無い鍵」を出す |
| `知らせる` | 版が上がった・失敗した・再起動が要る・設定項目が増減した、を知らせるコマンド |

結果は `<手元>/更新の記録.log` に残ります。

結は**層**に分けられます。`紡.json` に、そのマシンからつなげる層を名前付きで並べます（`結` は `個人` の層の別名）:

```json
{ "結": { "アドレス": "127.0.0.1:7952" },
  "結の層": { "useai": { "アドレス": "127.0.0.1:7953" }, "reatex": { "アドレス": "127.0.0.1:7954" } } }
```

`所属.json` の一番上の `結` に、その所属が**使える層**と**既定の書き先**を書きます:

```json
"結": { "既定": "reatex", "使える": ["個人", "useai", "reatex"] }
```

セッションからは `tsumugi yui '<問い合わせ>'` が既定の層、`tsumugi yui --層 <名前> '<問い合わせ>'` がその層（`--共有` は `--層 個人`）。
使えない層は、通る道（使える層）を添えて断ります。既定でない層に書いたときは「★…の層に書きました」と出します。
紡が起こすセッションには、その所属の使える層と使い分けを決まりとして渡します。

★**紡の「使える」は柵であって、仕切りではありません。**同じマシンの同じユーザーなら、どの層の合言葉のファイルも読めるので、
セッションが紡を通さずに直接つなげば越えられます。うっかり混ぜないためのものです。本当に分けるには、
デーモン（ファイル）を分けたうえで、合言葉をセッションから読めない場所に置く必要があります。

別の筐体から結の LAN の口（`--lan`）につなぐときは、合言葉の**出どころ**を書きます（値そのものは書かない）:

```json
{ "結": { "アドレス": "192.168.1.23:7952", "合言葉ファイル": "~/.yui-secret" } }
{ "結": { "アドレス": "192.168.1.23:7952", "合言葉コマンド": ["security", "find-generic-password", "-s", "tsumugi-yui", "-w"] } }
```

`合言葉ファイル` は本人だけが読める権限で置く。`合言葉コマンド` は値を標準出力に出すもの（macOS の Keychain など）。
`tsumugi yui` は最初の 1 行で合言葉を送り、通らなければ止まります（値は画面にも記録にも出しません）。

`マシン` は書かなければホスト名から作ります（WSL では `ホスト名/ディストロ名`）。
★**WSL では必ず書いてください。** ディストロ名を教える `WSL_DISTRO_NAME` は、systemd の timer や
Claude Code の背景セッションには渡りません。書かないと、手で叩いたときと自動のときで名前が変わり、
自分のセッションを「よそのマシン」とみなして起こさず・定時を届けません（結の書き手も割れます）。
環境変数 `TSUMUGI_MACHINE` があれば、それが先です。

| キー | 要るか | 意味 |
|---|---|---|
| `名前` | 要る | セッション名。所属をまたいで重ならないように付ける |
| `作業フォルダ` | 要る | ここで起こす。Claude Code で「信頼済み」にしておく（または `信頼する`） |
| `常駐` | | `false` なら常駐しない。run は起こさず、定時・届けが来たときだけ起こして渡す（下の「常駐しないセッション」）。無ければ `true`（止まっていれば run が起こし直す） |
| `信頼する` | | `true` なら、紡が起こす直前に、`作業フォルダ` を Claude Code の「信頼済み」にする（下の「作業フォルダの信頼」） |
| `最初の指示` | | 初めて起こすときに渡す |
| `権限モード` | | `claude --permission-mode` に渡す |
| `モデル` | | `claude --model` に渡す |
| `引き継ぐ会話` | | 既存の会話の ID。その会話を写して起こす（よそで始めた会話を紡に移すとき）。`最初の指示` があれば付けて渡す。★元の会話が止まっていると、写しでなく同じ ID のまま起きることがある（2.1.326） |
| `マシン` | | 動かすマシン（ホスト名。WSL では `ホスト名/ディストロ名`）。書けば、ほかのマシンの紡はそのセッションを起こさず・止めない。`tsumugi l` には「（よそのマシン）」と出る |
| `定時` | | 決まった時刻に届ける指示の並び。`{"いつ": "0 9 * * *", "指示": "…"}`（cron 5 項目・ローカル時刻）か `{"日時": "2026-11-28 09:00", "指示": "…"}`（一度だけ） |
| `メモ` | | 人が読むための書き置き |

紡が起こしたセッションには、Claude Code のローカルメモリを切る設定（`autoMemoryEnabled: false`）を必ず付けます。
質問の道具（AskUserQuestion）も使えなくします（`--disallowedTools`）。無人のセッションでは、質問の画面が人の答えを待って止まるためです（`askUserQuestionTimeout` は背景のセッションに効かない）。

紡は起こしたセッションの会話 ID を `<所属>/状態.json` に控え、**同じ会話 ID・同じ名前のまま**揃えます（`claude agents` と `tsumugi l` が同じに見えるように）。

- 止まったもの（WSL を起こし直したあとの failed も）は `claude respawn <ID>` で起こし直す。止まっているものへの定時・届けも、`claude respawn` で起こしてからチャネルで渡す
  （CLI からの `--resume` は Claude Code の予備のプロセスを使うと新しい ID の写しになるため。`claude respawn` は予備を使っても同じ ID）。
- Claude Code が紡の設定（名前・チャネル・権限モード・env）を覚えていない会話は、止める → `claude rm`（Claude Code 側の記録だけ外す。会話は残る）→
  紡のフラグと「付け直した」知らせを付けて `--resume <同じ ID>` で付け直す。動いているものは空いているときに行う。
- 所属.json の名前で手で起こした背景セッションは、同じ ID のまま紡の設定で配下に入れる。所属.json に無い名前のものは、その機の所属に「常駐しない」で足す。
  画面で開いているもの（interactive）には触らない（一覧には出す）。中身の無い会話は入れず、3 分たっても空なら止めて一覧から外す。
- `claude agents` の Completed のうち、紡が過去に管理していたもの（前の会話・同じ名前の古い会話）は `claude rm` で片付ける（会話の記録は残る。`tsumugi tree` に出る）。紡と関係の無いものは残す。
- Claude Code の daemon が立ち上がって 2 分は、run は何もしない（立ち上がった直後は死んだ会話を「動いている」と返したり、`--resume` が空の会話を作ったりするため）。

### 常駐しないセッション

背景のセッションは 1 本ごとにメモリを使います（UseAI の WSL で 1 本 350〜400MB）。いつも動いている必要が無いものは
`"常駐": false` にすると、必要なときだけ起きます。

- run は、止まっているのを見ても起こし直しません。まだ一度も起こしていないものも起こしません。
- 定時と届けは今までどおり渡します。止まっていれば、同じ会話のまま指示を付けて起こします。
  まだ一度も起こしていなければ、`最初の指示` と、定時・届けの指示の両方を付けて、最初の起動として起こします。
- 渡したあと、紡は止めません（Claude Code が、手の空いたセッションを自分で片付けます）。
- `tsumugi a <名前>` と `tsumugi 名前を変える` は、今までどおり、止まっていれば起こします。
- `tsumugi l` と `tsumugi status` には「止まっている（必要なときに起こす）」と出ます。見張りは、止まっていることを異常として知らせません。

★**止まっているセッションには、ほかのセッションからの SendMessage が届きません**（`ListAgents` にも出ません）。
常駐しないセッションへの連絡は `tsumugi 届ける <名前> "…"` で送ってください（止まっていれば起こして渡します）。

### 作業フォルダの信頼

Claude Code は、初めて開くフォルダで「このフォルダを信頼するか」を人に聞きます。
フォルダの中の設定（`.claude/settings.json` のフック・`.mcp.json` の MCP サーバーなど）は、開いただけで
コマンドを動かせるので、知らないフォルダのものが勝手に動かないよう、人が一度見てから許す、という守りです。
信頼していないフォルダでは、背景のセッション（`--bg`）は起きません（`Workspace not trusted`）。

`"信頼する": true` は、**この確認を、所属.json を書いた人の判断で先に済ませておく**ものです。
紡は、そのセッションを起こす直前（`run` の「起こす」「写して起こす」）にだけ、`~/.claude.json` の
`projects.<作業フォルダの絶対パス>.hasTrustDialogAccepted` を `true` にします。

- 書くのは `"信頼する": true` と書いたセッションの `作業フォルダ` だけ。`false` や書いていないものには触りません。
  親のフォルダやほかのフォルダは信頼しません。
- `~/.claude.json` は Claude Code が動きながら書き換えるので、書く直前に読み直し、その 1 か所だけを変えます。
  ほかの鍵には触りません（並び順も保ちます）。書いたら読み戻して、その 1 か所のほかが変わっていないことを確かめます。
- 書く前の中身を `<手元>/設定の控え/.claude.json.bak-<時刻>` に残します（本人だけが読める権限。
  `~/.claude.json` にはアカウントの情報が入っているので、控えは要らなくなったら消してください）。
- `~/.claude.json` が無い・読めない（壊れている）ときは、書かずに止め、そのセッションは起こしません。
- 鍵の形は Claude Code が書いている形に合わせます。Linux・macOS は絶対パス、Windows は区切りを `/` にした形
  （`D:/Users/kenta/…`）。`CLAUDE_CONFIG_DIR` があれば、その中の `.claude.json` に書きます。

★**`"信頼する": true` は、そのフォルダの中身（フック・MCP・CLAUDE.md）を人が見て良しとしたフォルダにだけ書いてください。**
他人が書き換えられるフォルダ（共有フォルダ・clone したばかりのリポジトリ）に付けると、その中のフックが無人で動きます。

### クラウドのセッション

セッションの `"マシン"` を `"クラウド"`（または `"cloud"`）にすると、紡はそのセッションを claude.ai/code のクラウドで動かします。
扱うのは、その所属.json を持つマシンの紡です。

```json
{ "名前": "c-patrol", "作業フォルダ": "D:/Users/me/repo", "マシン": "クラウド", "最初の指示": "…", "定時": [{ "いつ": "0 * * * *", "指示": "…" }] }
```

- **起こす**: 一度も起こしていない常駐のセッションは、次の run が `claude --cloud "<最初の指示>"` で立て、`session_…` を控えます。
  クラウドのセッションを新しく立てるのは対話の画面だけなので、紡が自分で疑似端末（Windows は ConPTY、Linux・macOS は pty）を持って動かします。
  `作業フォルダ` は git のリポジトリにしてください（GitHub の remote があればそこを、無ければ手元のリポジトリを送ります。送る前に変更をコミットしておく）。
- **渡す**: 定時・届けは `claude -p "<指示>" --cloud <session_…>` で積みます。★積めたこと（`ok`）は、会話に入った証拠ではありません。
- **見えないもの**: クラウドのセッションは `claude agents` に出ないので、紡からは動いているか（idle・busy）が見えません。
  控えの ID があれば、クラウドに居るとみなします（眠っても会話は戻る）。`tsumugi l` には「クラウド（動いているかは見えない）」と出ます。
- `tsumugi a` は手元で開かず、開く URL を出します（★`claude --teleport` は使わない。手元に写しができ、紡が「手で起こしたもの」として所属に足してしまう）。`tsumugi 新しく` は新しいクラウドのセッションを立て、前のものは claude.ai/code に残します（要らなければ人がアーカイブ）。
  `tsumugi 止める --しばらく` は、届けを溜めておく印を付けるだけです（クラウドのセッション自体は止められません）。
- クラウドの中では、結（手元の 127.0.0.1）・紡のチャネル・手元の `~/.claude` の設定は使えません。claude.ai のコネクタは使えます。
