# 紡（tsumugi）

Claude Code を無人で走らせるための**仕組み**です。指示書・設計・道具を置きます。

**知識は置きません。** 知識は手元の [結（yui）](https://github.com/kentakusu/yui) に入れます。

| | 何を持つか | どこに在るか |
|---|---|---|
| **紡** | 仕組み（動かし方・決めごと・道具） | このリポジトリ（公開） |
| **結** | 知識（所属ごとの事情・手順・経緯） | 手元の `*.yui`（公開しない） |

## これは何か

作者が自分の運用に使うためのものです。**他の方が使われるなら「緩い前提」でお願いします。**
壊れても直す約束はしていません。

## 決めていること

- **Claude Code 前提です。** 他の AI 製品で動くことは狙いません。
- **tmux を使いません。** 依存を増やさないためです。セッション同士のやり取りは、
  Claude Code 標準のエージェント間メッセージ（`ListAgents` / `SendMessage`）を土台にします。
- **Claude Code のローカルメモリに頼りません。** 複数のクライアントや状況にまたがる知識は
  結に入れ、どこから起動しても同じものを引きます。
- **所属ごとに設定を分けます。** 仕組みは 1 つで共通、所属ごとのルール・知識・認証は
  手元の設定だけが持ちます（例: 自社 / 個人 / 業務委託先 A / 業務委託先 B）。
  手元を適切に設定すれば動く、を目指します。

## このリポジトリに入れないもの

- 結のデータ（`*.yui`）
- 所属ごとの設定と知識（`~/.tsumugi/` に置く。リポジトリの外）
- 認証情報

`.gitignore` で弾いていますが、**最後に確かめるのは commit する人です。**

## 状態

| コマンド | 状態 |
|---|---|
| `tsumugi status` | 在る。所属ごとに「要るセッション」と「実際に動いているもの」を並べる |
| `tsumugi run` | 在る。足りないものを起こし、紡が起こして要らなくなったものを止める（1 回流して終わる。`--dry` で見るだけ） |
| `tsumugi list`（`l`） | 在る。紡のセッションを番号・名前で並べる |
| `tsumugi attach`（`a`）`<名前\|番号\|ID>` | 在る。開く。番号は `list` の左端。止まっていれば同じ会話のまま起こしてから開く |
| `tsumugi 届ける`（`send`）`<名前> [指示…]` | 在る。外（受け口・人・道具）からセッションへ指示を渡す。すぐ渡せなければ `<所属>/届け待ち/` に置き、run が渡す（24 時間で諦めて知らせる） |
| `tsumugi yui <問い合わせ>…` | 在る。結のデーモンに名乗って問い合わせる。紡のセッションは結をこれで読み書きする |
| `tsumugi install` / `uninstall` | 在る。OS の定期実行に `tsumugi run`（5 分おき）を登録する / 外す。Linux（systemd の user timer）で確かめた。macOS（launchd）・Windows（タスク スケジューラ）は書いただけ |

設計は [docs/設計.md](docs/設計.md)、日々の使い方（前面と背景の行き来など）は [docs/使い方.md](docs/使い方.md)。

## 作り方

Go 1.27 が要ります。

```
go build -o tsumugi ./cmd/tsumugi      # Windows なら -o tsumugi.exe
go test ./...
```

Linux で動かして確かめています。Windows・macOS 向けは**ビルドが通ることまで**しか確かめていません。

## 所属の設定

`~/.tsumugi/<所属>/所属.json`（置き場所は環境変数 `TSUMUGI_HOME` で変えられます）。
フォルダ名がそのまま所属の名前になります。

```json
{
  "表示名": "自社",
  "セッション": [
    {
      "名前": "jisha-keiri",
      "作業フォルダ": "~/jisha-keiri",
      "最初の指示": "docs/TASK.md を読んで、話しかけられるまで待つ",
      "権限モード": "dontAsk"
    }
  ]
}
```

知らないキーは誤記として弾きます（黙って捨てません）。

所属ごとに `見張り` を書けます（書かなくても既定で見張り、run の出力に残します）:

```json
"見張り": { "止まり": "15m", "長すぎ": "3h", "知らせる": ["~/bin/notify.sh"] }
```

run のたびに、紡のセッションの様子（`claude agents --json` の state）を見て、
`blocked`（権限の確認・入力待ち）が `止まり` だけ、作業中が `長すぎ` だけ続いたら、1 回だけ知らせます。
`知らせる` はコマンドで、本文を標準入力と環境変数 `TSUMUGI_MESSAGE` で渡します（LW へ送る道具などを書く）。
届けを諦めたときも、ここへ知らせます。

所属をまたぐ設定は `~/.tsumugi/紡.json` に置きます。このマシンの名前と、結のデーモンのアドレスです。

```json
{ "マシン": "myhost/Ubuntu", "結": { "アドレス": "127.0.0.1:7952" } }
```

`マシン` は書かなければホスト名から作ります（WSL では `ホスト名/ディストロ名`）。
★**WSL では必ず書いてください。** ディストロ名を教える `WSL_DISTRO_NAME` は、systemd の timer や
Claude Code の背景セッションには渡りません。書かないと、手で叩いたときと自動のときで名前が変わり、
自分のセッションを「よそのマシン」とみなして起こさず・定時を届けません（結の書き手も割れます）。
環境変数 `TSUMUGI_MACHINE` があれば、それが先です。

| キー | 要るか | 意味 |
|---|---|---|
| `名前` | 要る | セッション名。所属をまたいで重ならないように付ける |
| `作業フォルダ` | 要る | ここで起こす。Claude Code で「信頼済み」にしておく |
| `最初の指示` | | 初めて起こすときに渡す |
| `権限モード` | | `claude --permission-mode` に渡す |
| `モデル` | | `claude --model` に渡す |
| `引き継ぐ会話` | | 既存の会話の ID。その会話を写して起こす（よそで始めた会話を紡に移すとき） |
| `マシン` | | 動かすマシン（ホスト名。WSL では `ホスト名/ディストロ名`）。書けば、ほかのマシンの紡はそのセッションを起こさず・止めない。`tsumugi l` には「（よそのマシン）」と出る |
| `定時` | | 決まった時刻に届ける指示の並び。`{"いつ": "0 9 * * *", "指示": "…"}`（cron 5 項目・ローカル時刻）か `{"日時": "2026-11-28 09:00", "指示": "…"}`（一度だけ） |
| `メモ` | | 人が読むための書き置き |

紡が起こしたセッションには、Claude Code のローカルメモリを切る設定（`autoMemoryEnabled: false`）を必ず付けます。

紡は起こしたセッションの会話 ID を `<所属>/状態.json` に控えます。止まったものは同じ会話を続ける形で起こし直します
（`claude --bg --resume <ID>` をフラグ無しで。フラグを付けると写しになるため）。
紡が起こしていないセッション（手で開いたものなど）には触りません。
