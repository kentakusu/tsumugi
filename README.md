# 紡（tsumugi）

Claude Code を無人で走らせるための**仕組み**です。指示書・設計・道具を置きます。

**知識は置きません。** 知識は手元の [結（yui）](https://github.com/kentakusu/yui) に入れます。

| | 何を持つか | どこに在るか |
|---|---|---|
| **紡** | 仕組み（動かし方・決めごと・道具） | このリポジトリ（公開） |
| **結** | 知識（所属ごとの事情・手順・経緯） | 手元の `*.yui`（公開しない） |

## これは何か

作者が自分の運用に使うためのものです。**他の方が使われるなら「緩い前提」でお願いします。**
壊れても直す約束はしていません。

## 決めていること

- **Claude Code 前提です。** 他の AI 製品で動くことは狙いません。
- **tmux を使いません。** 依存を増やさないためです。セッション同士のやり取りは、
  Claude Code 標準のエージェント間メッセージ（`ListAgents` / `SendMessage`）を土台にします。
- **Claude Code のローカルメモリに頼りません。** 複数のクライアントや状況にまたがる知識は
  結に入れ、どこから起動しても同じものを引きます。
- **所属ごとに設定を分けます。** 仕組みは 1 つで共通、所属ごとのルール・知識・認証は
  手元の設定だけが持ちます（例: 自社 / 個人 / 業務委託先 A / 業務委託先 B）。
  手元を適切に設定すれば動く、を目指します。

## このリポジトリに入れないもの

- 結のデータ（`*.yui`）
- 所属ごとの設定と知識（`~/.tsumugi/` に置く。リポジトリの外）
- 認証情報

`.gitignore` で弾いていますが、**最後に確かめるのは commit する人です。**

## 状態

| コマンド | 状態 |
|---|---|
| `tsumugi status` | 在る。所属ごとに「要るセッション」と「実際に動いているもの」を並べる |
| `tsumugi run` | 在る。足りないものを起こし、紡が起こして要らなくなったものを止める（1 回流して終わる。`--dry` で見るだけ） |
| `tsumugi list`（`l`） | 在る。紡のセッションを番号・名前で並べる |
| `tsumugi attach`（`a`）`<名前\|番号\|ID>` | 在る。開く。番号は `list` の左端。止まっていれば同じ会話のまま起こしてから開く |
| `tsumugi 届ける`（`send`）`<名前> [指示…]` | 在る。外（受け口・人・道具）からセッションへ指示を渡す。すぐ渡せなければ `<所属>/届け待ち/` に置き、run が渡す（24 時間で諦めて知らせる） |
| `tsumugi 更新`（`update`）`[--dry] [紡\|claude\|OS\|設定項目]…` | 在る。項目を書けばそれだけ（例: `tsumugi 更新 紡`）。Claude Code（`claude update`）と OS のパッケージ（Ubuntu: apt / macOS: brew / Windows: winget）を新しくする。`紡.json` の「更新」に時刻を書けば run が毎日やる。古い版で動いている空きセッションを、同じ会話のまま入れ直す |
| `tsumugi 設定項目`（`settings`）`[--dry]` | 在る。Claude Code の設定項目の一覧を取り、前回からの増減と、手元の設定にある「一覧に無い鍵」を出す |
| `tsumugi 設定そろえ`（`align-settings`）`[--dry]` | 在る。Claude Code のユーザー設定（`~/.claude/settings.json`）を、基本の値 [`settings/claude-base.json`](settings/claude-base.json) と比べる。書き換えるのは `紡.json` の `"設定を合わせる"` に載せた鍵だけ（`["*"]` で全部）。前の値・後の値を `<手元>/設定そろえの記録.log` に残す。毎日の更新（`設定項目`）でも見る |
| `tsumugi チャネル準備`（`channel-setup`） | 在る。動いているセッションへ**止めずに**渡すチャネル（Claude Code の channels・研究プレビュー）の準備。プラグインを入れ、マシンの管理設定に許可があるかを見る（無ければ打つものを出す） |
| `tsumugi yui <問い合わせ>…` | 在る。結のデーモンに名乗って問い合わせる。紡のセッションは結をこれで読み書きする |
| `tsumugi install` / `uninstall` | 在る。OS の定期実行に `tsumugi run`（5 分おき）を登録する / 外す。Linux（systemd の user timer）・Windows（タスク スケジューラ・管理者不要・TSUMUGI_HOME もタスクに渡る）・macOS（launchd・2026-11-22 Mac mini で実測）で確かめた |

純正機能との対応（純正でできることは純正に寄せる）は [docs/純正との対応.md](docs/純正との対応.md)。
設計は [docs/設計.md](docs/設計.md)、日々の使い方（前面と背景の行き来など）は [docs/使い方.md](docs/使い方.md)。

## 作り方

Go 1.27 が要ります。

```
go build -o tsumugi ./cmd/tsumugi      # Windows なら -o tsumugi.exe
go test ./...
```

Linux（Ubuntu）・Windows・macOS（Apple Silicon）で動かして確かめています。

## 所属の設定

`~/.tsumugi/<所属>/所属.json`（置き場所は環境変数 `TSUMUGI_HOME` で変えられます）。
フォルダ名がそのまま所属の名前になります。

```json
{
  "表示名": "自社",
  "セッション": [
    {
      "名前": "jisha-keiri",
      "作業フォルダ": "~/jisha-keiri",
      "最初の指示": "docs/TASK.md を読んで、話しかけられるまで待つ",
      "権限モード": "dontAsk"
    }
  ]
}
```

所属.json の知らないキーは誤記として弾きます（黙って捨てません）。
`紡.json` の知らないキーは、新しい版の紡が足したものかもしれないので、飛ばして読み、知らせます（古い版の紡で、マシン名やチャネルまで読めなくならないように）。
★`紡.json` に新しいキーを足すときは、**先に各マシンの紡を新しくしてから**足してください。

所属ごとに `見張り` を書けます（書かなくても既定で見張り、run の出力に残します）:

```json
"見張り": { "止まり": "15m", "長すぎ": "3h", "知らせる": ["~/bin/notify.sh"] }
```

run のたびに、紡のセッションの様子（`claude agents --json` の state）を見て、
`blocked`（権限の確認・入力待ち）が `止まり` だけ、作業中が `長すぎ` だけ続いたら、1 回だけ知らせます。
`知らせる` はコマンドで、本文を標準入力と環境変数 `TSUMUGI_MESSAGE` で渡します（LW へ送る道具などを書く）。
紡のセッションに知らせるなら `["tsumugi", "届ける", "<名前>"]`（run の中からは届け待ちに置くだけで、次の run が渡す）。
届けを諦めたときも、ここへ知らせます（★`知らせる` が無いあいだは、届けを諦めずに置いておきます。黙って捨てないため）。

所属をまたぐ設定は `~/.tsumugi/紡.json` に置きます。このマシンの名前と、結のデーモンのアドレスです。

```json
{ "マシン": "myhost/Ubuntu", "結": { "アドレス": "127.0.0.1:7952" } }
```

チャネル（動いているセッションへ止めずに渡す）: `tsumugi チャネル準備` が全部 ○ になったら `"チャネル": true` を足す。
紡が起こすセッションに `--channels plugin:tsumugi-channel@tsumugi` が付き、定時と届けはソケット（`<手元>/<所属>/<名前>.sock`）
へ書くだけになる（止めない・作業中でも次のターンで入る）。チャネルが応えないセッションには、今までどおり止めて渡す。

更新（セキュリティのため、いつも最新を使う）:

```json
"更新": { "いつ": "30 4 * * *", "紡": true, "claude": true, "OS": true, "入れ直し": true, "設定項目": true,
          "ほか": [["mise", "upgrade"]], "知らせる": ["~/bin/notify.sh"] }
```

| キー | 意味 |
|---|---|
| `いつ` | cron 5 項目。来たら run が 1 回 更新する（書かなければ `tsumugi 更新` を手で）。機械が寝ていて逃しても、24 時間以内に起きれば追いかける。更新は run とは別の錠で回すので、長い更新の間もほかの run は起こす・届けるを続ける。1 つのコマンドは 2 時間で打ち切る |
| `紡` | 紡そのものを新しくする。main に push するたびに Actions が各 OS 向けの実行ファイルを [Release](https://github.com/kentakusu/tsumugi/releases) に置くので、それを取り、`SHA256SUMS` で確かめてから置き換える。Release のほうが新しいときだけ（手元の変更が入ったビルドは置き換えない）。Windows は動いている exe を `.old` に退けてから置く |
| `claude` | `claude update`（純正の更新を呼ぶだけ） |
| `OS` | Ubuntu/Debian: `sudo -n apt-get update` と `upgrade`（パスワードを聞かれる環境では止まらず失敗として知らせる）／macOS: `brew update`・`brew upgrade`／Windows: `winget upgrade --all --scope user --silent`（管理者権限が要るものは無人では入らないので、残りを一覧にして記録に出す。人が手で入れる）。**再起動はしない**（要るときは知らせる） |
| `ほか` | ほかに流すコマンドの並び |
| `入れ直し` | run のたびに、claude の実行ファイルより前に起きた・空いている紡のセッションを、同じ会話のまま起こし直す（作業中・入力待ちには触らない） |
| `設定項目` | 設定項目の一覧（SchemaStore の JSON Schema）を取り、増減と「一覧に無い鍵」を出す |
| `知らせる` | 版が上がった・失敗した・再起動が要る・設定項目が増減した、を知らせるコマンド |

結果は `<手元>/更新の記録.log` に残ります。

別の筐体から結の LAN の口（`--lan`）につなぐときは、合言葉の**出どころ**を書きます（値そのものは書かない）:

```json
{ "結": { "アドレス": "192.168.1.23:7952", "合言葉ファイル": "~/.yui-secret" } }
{ "結": { "アドレス": "192.168.1.23:7952", "合言葉コマンド": ["security", "find-generic-password", "-s", "tsumugi-yui", "-w"] } }
```

`合言葉ファイル` は本人だけが読める権限で置く。`合言葉コマンド` は値を標準出力に出すもの（macOS の Keychain など）。
`tsumugi yui` は最初の 1 行で合言葉を送り、通らなければ止まります（値は画面にも記録にも出しません）。

`マシン` は書かなければホスト名から作ります（WSL では `ホスト名/ディストロ名`）。
★**WSL では必ず書いてください。** ディストロ名を教える `WSL_DISTRO_NAME` は、systemd の timer や
Claude Code の背景セッションには渡りません。書かないと、手で叩いたときと自動のときで名前が変わり、
自分のセッションを「よそのマシン」とみなして起こさず・定時を届けません（結の書き手も割れます）。
環境変数 `TSUMUGI_MACHINE` があれば、それが先です。

| キー | 要るか | 意味 |
|---|---|---|
| `名前` | 要る | セッション名。所属をまたいで重ならないように付ける |
| `作業フォルダ` | 要る | ここで起こす。Claude Code で「信頼済み」にしておく |
| `最初の指示` | | 初めて起こすときに渡す |
| `権限モード` | | `claude --permission-mode` に渡す |
| `モデル` | | `claude --model` に渡す |
| `引き継ぐ会話` | | 既存の会話の ID。その会話を写して起こす（よそで始めた会話を紡に移すとき）。`最初の指示` があれば付けて渡す。★元の会話が止まっていると、写しでなく同じ ID のまま起きることがある（2.1.326） |
| `マシン` | | 動かすマシン（ホスト名。WSL では `ホスト名/ディストロ名`）。書けば、ほかのマシンの紡はそのセッションを起こさず・止めない。`tsumugi l` には「（よそのマシン）」と出る |
| `定時` | | 決まった時刻に届ける指示の並び。`{"いつ": "0 9 * * *", "指示": "…"}`（cron 5 項目・ローカル時刻）か `{"日時": "2026-11-28 09:00", "指示": "…"}`（一度だけ） |
| `メモ` | | 人が読むための書き置き |

紡が起こしたセッションには、Claude Code のローカルメモリを切る設定（`autoMemoryEnabled: false`）を必ず付けます。
質問の道具（AskUserQuestion）も使えなくします（`--disallowedTools`）。無人のセッションでは、質問の画面が人の答えを待って止まるためです（`askUserQuestionTimeout` は背景のセッションに効かない）。

紡は起こしたセッションの会話 ID を `<所属>/状態.json` に控えます。止まったものは同じ会話を続ける形で起こし直します
（`claude --bg --resume <ID>` をフラグ無しで。フラグを付けると写しになるため）。
紡が起こしていないセッション（手で開いたものなど）には触りません。
