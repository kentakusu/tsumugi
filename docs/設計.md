# 紡の設計

★**まだ設計です。実装はありません。** 「実測」と書いたものだけが、手元で確かめた事実です。

## 1. 目的

Claude Code を、**複数の所属**（自社・個人・業務委託先など）ごとに、**無人で常駐**させる。

- Windows / macOS / Linux（Ubuntu）で動く
- OS のサービスとして常駐する（ログインしたら勝手に立ち上がる）
- 仕組みは公開、所属ごとの知識・認証・ルールは手元だけに置く

## 2. 分担

| 層 | 受け持つもの | 在りか |
|---|---|---|
| **Claude Code** | Claude の実行・バックグラウンド起動・セッション間メッセージ | 公式の CLI |
| **紡** | 「どの所属で、どのセッションを、何本」を保つ常駐プロセスと、その決めごと | このリポジトリ |
| **結** | 所属ごとの知識 | 手元の `*.yui`（所属ごとに 1 つ） |
| **手元の設定** | 所属ごとの指示・認証の切り替え | `~/.tsumugi/<所属>/`（公開しない） |

紡は **Claude を自分で抱えない。** 抱えるのは Claude Code の `claude daemon` で、紡はそれに
「足りないものを起こし、余計なものを止める」よう指示するだけにする（3 節）。

## 3. 土台にする Claude Code の機能（実測）

2026-11-15、Claude Code 2.1.322〜2.1.323、Linux（WSL2・Ubuntu 26.04）で確かめた。

| やりたいこと | Claude Code の機能 | 実測 |
|---|---|---|
| 端末なしで常駐させる | `claude --bg -n <名前> "<最初の指示>"` | 動く。tmux は要らない |
| 一覧を取る | `claude agents --json`（`name` `kind` `status` `sessionId` `cwd` `pid` `startedAt`） | 動く。`--all` で終わったものも出る |
| 止める・消す・中を見る | `claude stop` / `rm` / `logs` / `attach` / `respawn` | 動く |
| セッション同士で話す | `ListAgents` / `SendMessage`（Claude のツール） | **往復できた**（対話セッション → バックグラウンド → 返信） |
| 終わったら知らせてもらう | `SendMessage` の `notify_when_idle` | 購読できた |

踏んだところ:

- ★**バックグラウンドのセッションは、起動した側の環境変数を受け取らない。**
  受け取るのは、その時点で動いている `claude daemon` の環境変数。
  （1 本目の起動で daemon が立つので、1 本目だけは渡ったように見える。2 本目で別の値を渡すと、1 本目の値が出た）
  ⇒ **所属ごとの環境変数は `--settings '{"env":{...}}'` で渡す。** これはセッションごとに効いた。
  （公式の文書が「起動した側から受け継ぐ」と書いているのは `PATH` やモデルの別名など一部だけ）
- ★**「信頼」していないフォルダでは `--bg` が起動しない**（`Workspace not trusted`）。
  ⇒ 所属の作業フォルダは、登録するときに信頼を済ませておく必要がある。
  公式の文書にある手で済ませる方法は `~/.claude.json` の `projects["<フォルダ>"].hasTrustDialogAccepted` を
  `true` にすること（git の中ならリポジトリの最上位が単位）。**これで `--bg` が起動した（実測）。**
- `claude daemon` は**呼ばれたときだけ立ち、最後の利用者がいなくなると終わる。**
  この版では OS のサービスとしての登録は無効になっている（`claude daemon --help`）。
  ⇒ **ログイン時に立ち上げる役は紡が持つ。**
- 権限モードが違うセッションからのメッセージは、受け手側で人の承認待ちになる。
  ⇒ 1 つの所属の中では権限モードをそろえる。

★**`ListAgents` に出るのは同じマシン（WSL ならそのディストロ）のセッションだけ。**
別のディストロ・別のマシンのセッションは、**リモートコントロール（`/remote-control`、起動時なら
`--remote-control`）を有効にすると**アカウントの他のセッションとして見える（作者の観測。紡の実装で実測する）。
⇒ 所属やマシンをまたいで艦隊を見渡す・束ねるのは、リモートコントロールを土台にする。
★バックグラウンド起動（`--bg`）とリモートコントロールを同時に使えるかは未実測。

Windows は、`claude --help` と `claude daemon status` で同じコマンドが在ること
（受け口は名前付きパイプ `\\.\pipe\cc-daemon-*`）までを確かめた。
★**Windows でのバックグラウンド起動とメッセージの往復は未実測。macOS は何も試していない。**

## 4. 所属

所属 = 「誰の仕事として動くか」。例: 自社 / 個人 / 業務委託先 A / 業務委託先 B。

★**所属どうしは混ぜない。** 業務委託先の知識が別の所属のセッションに見えたら事故になる。

| 所属ごとに 1 つ | 例 |
|---|---|
| 手元のフォルダ | `~/.tsumugi/<所属>/` |
| 知識（結） | `~/.tsumugi/<所属>/知識.yui` |
| 指示（その所属の決めごと） | `~/.tsumugi/<所属>/指示.md` |
| 環境変数（認証の切り替え） | `~/.tsumugi/<所属>/settings.json` の `env`（例: `GH_CONFIG_DIR`、`GIT_CONFIG_GLOBAL`） |
| セッション名の頭 | `<所属>-<役割>`（例: `jisha-main`） |

- セッションを起こすとき、紡は**その所属のものだけ**を渡す（`--settings`、`--add-dir`、
  `--append-system-prompt-file`）。
- 所属をまたぐ `SendMessage` は**決めごとで禁止**する。★同じマシンのセッションは技術的には
  互いに送れてしまうので、決めごとだけでは防げない（7 節）。

## 5. 常駐（紡のデーモン）

**実装は Go。** 1 つのバイナリを Windows / macOS / Linux 向けに作り分けて配れるため。
中身は JSON の読み書き・プロセスの起動・OS ごとのサービス登録が中心で、C99 で 3 OS 分を書くより手間が小さい。
（結は C99 のまま。紡は結を CLI として呼ぶので、言語がそろっていなくてよい）

紡のデーモンがやることは 1 つ: **望む状態と実際を突き合わせて、差を埋める。**

```
望む状態:  ~/.tsumugi/*/所属.json   … この所属で、この名前のセッションを、この指示で 1 本
実際:      claude agents --json
差:        足りない → claude --bg で起こす / 余計 → claude stop / 落ちた → 起こし直す
```

- 一定間隔で回す。何度回しても結果が同じになるように作る。
- OS への登録は紡が受け持つ:

| OS | 登録先 |
|---|---|
| Linux | systemd のユーザーユニット（`systemctl --user`） |
| macOS | launchd の LaunchAgent |
| Windows | タスク スケジューラ（ログオン時に起動） |

コマンドの案:

```
tsumugi run         前で回す（デバッグ用）
tsumugi install     OS に登録する / uninstall で外す
tsumugi status      所属ごとに、望む状態と実際を並べて出す
```

## 6. 知識（結）

- 知識は**所属ごとの `知識.yui` に入れる。** セッションは結の CLI で引く・書く。
- ★**Claude Code の自動メモリには頼らない。** 端末やクライアントが変わっても、
  同じ所属なら同じ知識が引けるようにするため。止め方は、所属の `settings.json` に
  `"autoMemoryEnabled": false`（または環境変数 `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`）。
  実測: フォルダの `.claude/settings.local.json` に書いて `--bg` で起動したところ、メモリのフォルダは作られず、
  同じファイルの権限設定（deny）とそのフォルダの MCP は効いたまま。★フックと `CLAUDE.md` の読み込みはまだ見ていない。
- 結のファイルは公開リポジトリに入れない（`.gitignore` で `*.yui` を弾いている）。

## 実測（2026-11-15 追記・2.1.325）

- `claude agents --json` に `id`（短い ID）と `state` が増えた。動いているものだけ `pid` を持つ。
  終わったものは `--all` で `state: done / stopped` として残り、**同じ名前が何本も並びうる。**
- `claude --bg --resume <会話ID>`（フラグ無し）は、止まったセッションを**同じ ID・起こした時の設定のまま**続ける。
- 同じことをフラグ付きでやると、**写し（新しい ID）**になる（claude が note で言う）。
  ⇒ 紡の「起こし直し」はフラグ無し、「よその会話を移す」はフラグ付き（写し）で使い分ける。
- `claude stop <短い ID>` で止まり、会話は残る。`claude rm` で一覧から消える。
- ★**話しかけられないまま 61 分たつと、Claude Code がバックグラウンドセッションを自分で終わらせる**
  （daemon.log に `bg retire <id>: idle-prompt, idle 61m`）。そのあと誰もつながっていなければ、
  supervisor も 5 秒で抜ける（`idle 5s with no clients — exiting`）。設定で止める口は見つかっていない。
  会話は残り、`tsumugi run`（フラグ無しの `--resume`）で同じ ID のまま起き直すことを確かめた。
  ⇒ 「常駐」は、終わらされても紡が起こし直す形で作る。`tsumugi install` で run を定期的に回す。
- 放置で止められない条件を測った（2026-11-15、2.1.325、どちらもリモートコントロール無し・起こしたあと誰も触らない）:
  - 予約（CronCreate、6 日後に 1 回）を持たせたもの: **75 分たっても生きていた。**
  - 予約なし: 60 分で止められた（`bg retire …: settled, idle 60m`）。
  - ⇒ 予約を持つセッションは止められない。リモートコントロールにつながったセッションも猶予が延びる作りだが、そちらは切り分けて測っていない。
- `tsumugi install` の timer で、止められた `useai-tsumugi` が 5 分以内に同じ会話のまま起き直ることを確かめた（15:10 に止められ、15:15 に起こし直し）。

## 結（yui）とのつなぎ方（2026-11-15、結の側と相談して決めたこと）

- **1 つが持ち、ほかはつなぐ。** 結のデーモン（`yuid`）を 1 か所で立て、セッションはそこへつなぐ。
  マシンごとに別々に書いて後で合わせる形は採らない（結の id はファイル内の順番で決まるので、別々に書くと食い違う）。
- **紡のセッションが結に書き始めるのは、デーモン経由にしてから。** 書き手と時刻（帰属）は
  デーモンが自分の時計で押す。これは**あとから足せない**（帰属の無い記録が溜まってからでは取り返せない）。
- 帰属は「点と書き手の組ごとに 1 本」で、残るのは**最後に書いたのは誰か・いつか**だけ。履歴が要るものは、記録そのものを点として作る。
- デーモンが立っている間、同じファイルを `yui` コマンドから直接は開けない。全員デーモンを通す。
- 同じ PC の Windows と WSL は、`.wslconfig` の `networkingMode=Mirrored` なら `127.0.0.1` を共有するので、
  Windows で立てたデーモンに WSL から `127.0.0.1:<ポート>` でつながる（結の側で実測）。`NAT` だとつながらない。
- 別のマシンからつなぐ口（LAN ＋ 合言葉）は結の側で未実装。要るのは別のマシンが入るときだけ。
- 未決: 所属ごとに結のファイルとデーモンを分けるか（分けるつもり）、合言葉の分け方。

## 結（yui）のデーモンにつなぐとき（2026-11-15・結の開発側から聞いた）

正は結の README「デーモン（同時に読む・書く）」と `docs/デーモンの構想.md`。ここには紡が作るときに守ることだけ書く。

- **名乗りは接続ごと。** 名乗る文と書く文は同じ接続に入れる（名乗らない接続は読むだけ）。
- **やりとりは「長さ（10 進のバイト数）＋改行＋本文」。** 行区切りではない。
  返りは 1 行に 1 つの JSON で、文ごとに `{"kind":"end","rc":N}` が締めに来る。**rc は文ごとに見る。**
  返りが多すぎると打ち切られ、end に `"cut":true` が付く。**cut を無視しない**（「全部」と読まない）。
- **デーモンが居る間は CLI で同じファイルを開けない**（錠）。
  ⇒ 紡は「デーモンが居なければ CLI にする」という落とし方を**しない**。つながらなければ、つながらないと言う。
- パスを誤ると、デーモンは**空の新しいファイルで元気に立つ。** 2 度目以降の起動で「新しいファイルとして始めました」が出たらパス違い。
  ⇒ 紡がつないだとき「空」が返ったら、書き始める前に疑う。
- 帰属は名乗りから自動で付く。同じ点を何度も書くと最後の書き手と時刻だけが残る（履歴は点の側に持たせる）。
- 止まっているセッションに `claude --bg --resume <会話ID> "<指示>"` とすると、**同じ ID のまま起きて、その指示を受け取る**（写しにならない）。
  動いているセッションに同じことをすると**写しになる**。⇒ 外から指示を渡せるのは「止まっているとき」だけ。
  起こし直しのときに「予約を張り直して」等を渡す口に使える（2026-11-15 実測）。
