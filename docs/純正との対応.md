# 純正（Claude Code）との対応

方針: **Claude Code の純正機能でできることは、純正に寄せる。** 紡は「純正に無いところ」だけを持つ。
毎日の追従（紡の開発セッションの定時）で見直し、純正でできるようになったら紡から外す。

最後に見直した版: 2.1.332（2026-11-28 08:4x の追従・新しい版なし）

| やりたいこと | いまの純正 | 紡がやっていること | 純正に寄せられない理由・メモ |
|---|---|---|---|
| まとめ役と作業役・定時・共有の記憶をまとめて（クラウドで） | **Projects**（公開ベータ・Pro/Max/Ultra に順に配布）: まとめ役の会話＋スレッド（クラウドのセッション・要るものだけ手元で Remote Control）＋プロジェクトの指示とメモリ＋Overview。プロジェクトの中の scheduled tasks は同じスレッドを続けられる（code.claude.com/docs/en/claude-projects.md・routines.md の原文） | 紡の統括・作業役・定時・結がこれに当たる | ★2026-11-24 時点でこのアカウントには未配布（claude.ai/code の一覧に無い。claude.ai/cowork/projects は以前からある別の Projects）。届いたら寄せる候補の筆頭 |
| クラウドのセッションを紡から扱う | 立てる: `claude --cloud "<指示>"`（★対話の画面でしか立てられない。`-p` と組めない・2.1.331 で実測）。追いの指示: `claude -p "…" --cloud <ID> --output-format json`（`{ok,session_id,url}`。★ok は積んだだけ）。一覧と状態: ListAgents に `<名前> · cloud · idle` と出る（2026-11-24 実測）。眠ると VM は数分で止まり、長く放っておくと回収される（会話は戻る・裏の処理は戻らない）。定期実行の最短は 1 時間（routines の原文） | まだしない（試しの段） | ★渡したものが会話に入ったかを紡から確かめる口が無い（クラウドのセッションへの SendMessage は、こちらが bypassPermissions だと人の承認待ちで止まり返事も来ない見込み。2.1.332 で、止められたメッセージの確認に「Always deliver」が足された＝人が一度選べば次から届く見込み・未実測）。★claude.ai の画面を自動のブラウザで読むのはしない（ボット確かめで止まる・利用規約: watari-windows の判断）。立てたセッションの名前は中身から自動で付く |
| 背景でセッションを動かす | `claude --bg`・`/bg`・agent view | 起こすときに `--bg` を使う | 寄せている |
| 止まったら起こし直す | 無い（`claude daemon` のサービス登録は無効） | `run` を OS の定期実行（5 分おき）で回す。★pid の無い記録は state が blocked・working でも止まっているとして `claude respawn` し、一覧も「止まっている（記録は blocked）」と出す | 純正にできたら外す。★OS の再起動のあと、人の返事待ち（blocked）だった背景セッションは純正では起き直らず、pid の無い blocked の記録だけが残る（2.1.330・2026-11-23 Windows の再起動で実測: 08:09 の daemon の起動から 08:13 に紡が届けるまで spawn なし） |
| サインインしなくても動かす | 無い | Linux は linger。★Windows はしない（予定タスクは Interactive・`conhost.exe --headless` で窓を出さない） | ★Windows の S4U は 2026-11-23 に試して戻した: S4U（セッション 0）で起きた daemon と背景セッションに、サインインした画面（セッション 1）の claude から届かず attach できない。Windows は再起動のあと自動でサインインしてロックするので、普段はサインイン中と同じに動く |
| 放っておくと退役する | agent view の Ctrl+T（ピン留め）で残す | 退役したら同じ会話のまま起こし直す | ピン留めを CLI から付けられれば寄せる。★空きメモリが少ないと、Claude Code は空いている背景セッションを片付ける（daemon.log の `retire …: settled, idle 5m [low memory]`・`low memory (589MB free) — retiring settled workers before spawning`。2.1.332・2026-11-26 Windows 実測）。紡は次の run で起こし直すので、メモリが足りないままだと「片付ける → 起こし直す」を繰り返す（★実測: 11-26 09:05〜11-27 07:26 JST に low memory の退役が yui-windows 27・watari-windows 24・tsumugi-windows 43 回、daemon の起動 12 回。daemon.log の `[low memory]` を数えた） |
| 決まった時刻に指示を渡す | セッション内の CronCreate（セッションが消えると消える・2.1.330 から 30 日で切れる。2.1.329 で、前の版が保存した予約は新しいセッションでは張り直しが要るようになった）／クラウドの routines | `定時` | 手元で・セッションをまたいで残るものが無い |
| 外から指示を渡す | **channels**（研究プレビュー）: MCP サーバーが動いているセッションへ押し込む。自作のものは、マシンの管理設定 `allowedChannelPlugins` に載せると確認なしで背景のセッションでも使える（2026-11-21 実測・Max の個人アカウントでも効いた） | 紡チャネル（`tsumugi channel` をプラグインとして配る）。届け・定時はソケットへ書くだけ。チャネルが無いセッションには「止めて、指示を付けて同じ会話で起こす」に戻る | CLI・スクリプトから渡す口が無い |
| 止まったままを見張る | 無い | `見張り`（`claude agents --json` の state / status） | |
| セッション一覧 | `claude agents --json` | 一覧はこれを使う。所属と番号を足すだけ | 寄せている |
| 前面と背景の行き来 | `claude attach`・agent view | `attach` は止まっていれば起こしてから開く | |
| MCP の秘密を CLI に出さずに登録 | `claude mcp add-json <名前> -`（2.1.327。JSON を標準入力から読む） | しない | cc-34 の Chatwork は env ファイルを読むラッパーで同じことをしている。作り直すときはこちらに寄せる |
| 知識をまたいで持つ | 自動メモリ（手元・プロジェクトごと） | 切る。結（yui）に置く | 所属・マシンをまたいで同じものを引くため（鈴木さんの方針） |
| Claude Code の更新 | native の自動更新・`claude update` | `更新` で `claude update` を呼ぶだけ | 寄せている |
| 動いているセッションを新しい版へ | native の自動更新が、上げたときに背景セッションを起こし直すことがある（2.1.327・2.1.330 では起こし直した。2.1.328 では起こし直さず、紡の入れ直しが 10:34 に respawn した）。★起こし直しの数秒の間に紡が --resume すると写しができる（2.1.330 で実測）ので、紡は起こし直す前に 30 秒まで見直す。手でやるなら `claude respawn <id>\|--all` | `入れ直し` は「どれが古いか・空いているか」を選んで `claude respawn` を呼ぶだけ | 寄せた（同じ会話 ID・同じ名前のまま。実測） |
| 指示を付けて起こす | `--resume <id> "<指示>"`（止まっている会話へ） | 定時・届け | ★起こしたときと違う版で渡すと写し（新しい ID・中身から付く名前）になることがある。紡は会話 ID で追い、写しを引き取る |
| OS の更新 | 対象外 | `更新` の `OS`（apt / brew / winget） | Windows の winget は、管理者権限が要るものを含めると約 14 時間 返らなかった（2026-11-21・消去法で特定）。ユーザーの範囲だけを上げ、残りは一覧にする。外すものは紡の設定でなく純正の `winget pin`（ブロックでない種類）。外しているものは毎回 `winget pin list` で記録に出す |
| 設定項目の追従 | 公式 docs・SchemaStore | `設定項目`（一覧の増減と、一覧に無い鍵） | 一覧は SchemaStore（公式 docs の写し・遅れることがある） |
