# 使い方

## 常駐のさせ方

紡は自前で常駐しません。`tsumugi install` が OS の定期実行に `tsumugi run` を 5 分おきで登録し、
落ちたセッションはそこで起こし直されます（`run` は何度流しても同じ結果になる）。

| OS | 登録先 | 確かめたか |
|---|---|---|
| Linux | systemd の user timer（`~/.config/systemd/user/tsumugi.{service,timer}`） | 確かめた |
| macOS | launchd の LaunchAgent（`~/Library/LaunchAgents/io.github.kentakusu.tsumugi.plist`） | 書いただけ |
| Windows | タスク スケジューラ（タスク名 `tsumugi`） | 書いただけ |

- 登録したときの `PATH` を持たせます（セッションが使う `node` などを見つけるため）。PATH を変えたら `tsumugi install` をやり直します。
- Linux はログアウト中も動かすなら一度だけ `loginctl enable-linger`。
- Linux の service は `KillMode=process`。既定のままだと、`run` が起こした Claude Code の supervisor が `run` の終わりに一緒に殺されます。
- ★WSL では、ディストロそのものが止まると何も動きません。WSL は既定で、使われていないディストロを 15 秒、VM を 60 秒で止めます。
  Windows 側の `%USERPROFILE%\.wslconfig` で止めないようにしておきます:

  ```
  [wsl2]
  vmIdleTimeout=-1

  [general]
  instanceIdleTimeout=-1
  ```

  （作者の環境はこの設定で動いています。Windows の起動時に WSL を起こす手当ては、まだ書いていません）

### 放置すると止まる件

Claude Code は、入力待ちのまま約 1 時間 誰もつないでいないバックグラウンドセッションを止めます
（会話は残る）。紡は止まったものを 5 分おきに起こし直すので、話しかけられない時間が続いても、遅くとも数分で戻ります。

止めさせない方法として公式に書かれているのは、agent view で **Ctrl+T（ピン留め）** することです。
セッションに予約（CronCreate）を持たせると止められないことも、実測で確かめました（予約なしは 60 分で止まり、予約ありは 75 分たっても生きていた）。

## 前面と背景の行き来

| したいこと | 操作 |
|---|---|
| 背景のセッションを前面で開く | `tsumugi a <名前>` または `tsumugi a <番号>`（番号は `tsumugi l` の左端。止まっていれば起こしてから開く） |
| 開いたセッションから抜ける（止めない） | 空のプロンプトで `←`、または `/exit`、`Ctrl+Z`（シェルへ戻る）、`Ctrl+C` を 2 回 |
| 前面で始めた会話を背景へ移す | その会話の中で `/bg`（`/background`）。空のプロンプトで `←` でも agent view へ回る |
| 前面で始めた会話を紡の管理下に入れる | `所属.json` の `引き継ぐ会話` にその会話の ID を書いて `tsumugi run`（写しとして起きる） |

- `claude attach` の中の `Ctrl+Z` は、OS のジョブ制御（一時停止）ではなく、Claude Code が受けて
  「シェルへ戻る」として扱います。抜けてもセッションは背景で動き続けます。
- 抜けずにターミナルを閉じても、セッションは止まりません（attach しているのは窓だけ）。

### Windows のターミナル

- Windows ネイティブで動かすなら、操作は同じです（`tsumugi attach`、抜けるのは `←`）。
  `attach` 直後 0.5 秒以内の `←` は「Ambiguous ←, press again to detach」と出るので、もう一度押します（公式の記述）。
- Windows の `Ctrl+Z` が抜ける操作として効くかは、まだ確かめていません。**確実なのは `←` と `/exit`。**
- WSL の中で動かしているセッションを Windows Terminal から開くなら:
  `wsl.exe -d <ディストロ> -- bash -lc "tsumugi attach <名前>"`。
  Windows Terminal のプロファイルに登録しておくと、タブ 1 つで開けます。
- 別の WSL・別のマシンのセッションは `ListAgents` に出ません。まとめて見るには Remote Control を使います（未整理）。

## 結（yui）を読み書きする

紡のセッションは、結を**必ずデーモン（`yuid`）を通して**読み書きします。所属をまたいで 1 つのデーモンにつなぎます。

```
tsumugi yui '一覧 (決定:)'
tsumugi yui '作る (決定:"…")' '一覧 (決定:)'     # 1 本の接続で順に
echo '一覧 (決定:)' | tsumugi yui                # 標準入力を 1 件として
```

- つなぐたびに `名乗る` を送ります。名乗りは紡が起こしたセッションなら `<所属>/<名前>@<マシン>`、
  それ以外は `人:<ユーザー>@<マシン>`。デーモンがこれと時刻を「書いた」として記録します。
- 返りは結の JSON の行をそのまま出します（名乗りの返りは出さない）。どれか 1 つでも失敗なら終了コード 1。
- ★デーモンにつながらないときは止まって知らせます。`yui` コマンドでファイルを直接開きに行きません
  （デーモンの錠が無い隙に開くと、次にデーモンが立てなくなる）。
- 紡が起こすセッションには、この決まりを `--append-system-prompt` で渡し、`TSUMUGI_AFFILIATION` / `TSUMUGI_SESSION` を環境変数で渡します。
- デーモンを立てるのは紡ではありません（Windows ならタスク スケジューラのログオン時。立て方は結の README「常駐させる」）。
